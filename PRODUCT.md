# Product

## Register

brand

## Platform

web

## Users

The primary audience is indie developers already using OpenAI-compatible SDKs, editors, agents, and local tools. They want to reuse authenticated local AI sessions and explicit external providers without rebuilding their workflow around a different API shape.

## Product Purpose

Claw Proxy exposes a Claude-first, multi-provider runtime through one OpenAI-compatible HTTP service. Success means a developer understands the value in seconds, can connect an existing client in minutes, and chooses to star the repository because it removes a real integration headache.

## Positioning

Keep the OpenAI-compatible tools you already use; route them through one local, Claude-first bridge with explicit support for configured external models.

## Conversion & proof

- Primary CTA: star the repository.
- Secondary CTA: install and run the proxy locally.
- The line a visitor remembers after 10 seconds: “One OpenAI-compatible endpoint. Claude by default. Other providers when you ask for them.”
- Belief ladder: it works with familiar clients; it reuses the authenticated local Claude CLI; setup is short; the default route remains local and explicit; the project is operationally serious enough to trust.
- Proof on hand: working OpenAI Chat Completions and Responses surfaces, dynamic model discovery, session continuity, health and metrics endpoints, an operator dashboard, deployment guides, tests, and public project activity.

## Brand Personality

Electric, capable, and independent. The voice is direct and technically credible, with neon cyberpunk energy used as a memorable identity rather than gamer decoration.

## Anti-references

Avoid generic AI-startup gradients, crypto/Web3 symbolism, esports branding, fake terminal cosplay, decorative glass panels, and unsupported claims. The project should feel like real infrastructure with an unmistakable indie edge.

## Design Principles

1. Lead with the one-minute win before exposing the full system.
2. Make the bridge visible: familiar client in, Claude Max out.
3. Use technical proof as persuasion, not as a wall of features.
4. Keep every claim honest about local security and subscription behavior.
5. Reward scanning while preserving a deep path for operators and contributors.

## Accessibility & Inclusion

Keep copy readable at GitHub’s default sizes, provide meaningful image alt text, never encode essential meaning in color alone, and ensure the README remains complete when images do not load or motion is unavailable.
